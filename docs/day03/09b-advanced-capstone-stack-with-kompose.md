# 9. Advanced hands-on: the Day 2 capstone stack with `kompose`

Port the three-tier stack of [Day 2, section 7](../day02/07-lab.md) (FastAPI ingestion API + PostgreSQL + Redis).

In Hands-on 7 you did this by hand for the smaller [Day 2, section 6](../day02/06-docker-compose.md) stack; here you start from `kompose` output and then harden it.

## 9.1 Step 1: build and push the API image (if needed)

If the image was not published during [Day 2](../day02/07-lab.md), build and push it now:

```bash
cd ~/meditwin-climate-capstone
docker build -t climate-ingestion-api:1.0.0 .

docker login gitlab.data.meditwin-project.eu:6443 -u traineeNN
docker tag climate-ingestion-api:1.0.0 \
  gitlab.data.meditwin-project.eu:6443/training/autumn-2026/climate-telemetry-traineeNN/climate-ingestion-api:1.0.0
docker push gitlab.data.meditwin-project.eu:6443/training/autumn-2026/climate-telemetry-traineeNN/climate-ingestion-api:1.0.0
```

Then make sure the API manifest generated by `kompose` points to this registry image and not to a local-only tag.

## 9.2 Step 2: generate a first draft with `kompose`

```bash
cd ~/meditwin-climate-capstone
mkdir -p k8s && kompose convert -f compose.yaml -o k8s/
ls k8s/
```

Read the output against the Day 3 cheat sheet before applying anything. Expect to fix at least these:

- **`api` image path**: `api-deployment.yaml` keeps `climate-ingestion-api:1.0.0` (local-only). Replace it with your pushed registry image, for example `.../climate-telemetry-traineeNN/climate-ingestion-api:1.0.0`.
- **Private registry pull**: add `imagePullSecrets: [{name: gitlab-registry}]` in the API Pod spec, as in Hands-on 2.
- **Plain-text credentials**: both `api-deployment.yaml` and `db-deployment.yaml` include `POSTGRES_*` values in clear text. Move them to a Secret and consume with `envFrom` or `secretKeyRef`.
- **Missing Services for discovery**: this output has `api-service.yaml` and `portainer-service.yaml`, but no Service for `db` or `cache` because those services had no published ports in Compose. Add `db-service.yaml` (5432) and `cache-service.yaml` (6379), otherwise `DB_HOST=db` / `REDIS_HOST=cache` will not resolve.
- **Probes/resources mostly absent**: add at least API readiness on `/health`, plus basic requests/limits, before treating the manifests as production-like.
- **`depends_on` disappears by design**: Kubernetes does not serialize startup. Keep retries in the app and rely on readiness to control traffic.
- **PVC scope**: in this output, PVCs are generated for `db` and `portainer` (not for `cache`, which is intentionally ephemeral). Keep `strategy: Recreate` for workloads with a single-writer PVC.
- **`portainer` in Kubernetes**: treat it as optional and usually remove it from this exercise. The Compose Docker-socket pattern does not translate directly to a Kubernetes cluster.
